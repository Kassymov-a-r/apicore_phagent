# Бесплатный запуск на Render

Используется тот же Render workspace `My Workspace`, где размещён Instagram-сервис `apicore_phagent` (https://apicore-phagent.onrender.com). Репозиторий: https://github.com/Kassymov-a-r/apicore_phagent. Новый бот находится в папке `video_uniquifier`, в отдельной ветке `feature/telegram-video-uniquifier`.

## Конфигурация

`video_uniquifier/render.yaml` создаёт один **Web Service с тарифом `free`**. Платных дисков, workers, баз данных или очередей нет. Корневой Blueprint относится к Instagram-приложению; при создании нового сервиса нужно выбрать именно Blueprint из подпапки.

| Настройка | Значение |
| --- | --- |
| Сервис | `telegram-video-uniquifier` |
| Runtime / регион | Docker / Oregon |
| Тариф | `free` |
| Dockerfile Path | `./video_uniquifier/Dockerfile.render` |
| Docker Context | `./video_uniquifier` |
| Запуск | `python -m uniquifier.web` |
| Health check | `/healthz` |
| Ветка | `feature/telegram-video-uniquifier` |
| Автодеплой | Выключен |
| Вход / выход | Файл в чате до 20 MiB; через кнопку до 200 MiB / результат до 50 MiB |
| Длительность / кадр | До 90 секунд / 2 073 600 пикселей (1080p, включая вертикальное видео) |
| Обработка | Один ролик, пять файлов последовательно; CRF 16, preset veryfast, один поток FFmpeg |

Большие ролики отклоняются с объяснением; разрешение и качество автоматически не уменьшаются. `veryfast` ускоряет кодирование по сравнению с локальным `slow`; при том же CRF размер результата может вырасти. Эти пределы снижают нагрузку, но не гарантируют завершение обработки на малом ресурсе Free.

## Запуск

1. Опубликовать подготовленную ветку в указанном GitHub-репозитории. Для деплоя Render должен видеть эту ветку и папку проекта в GitHub.
2. В Render создать отдельный Web Service из ветки `feature/telegram-video-uniquifier` с Dockerfile и Context из таблицы, выбрать **Free**. Либо создать Blueprint из `video_uniquifier/render.yaml` (не корневого файла).
3. В Environment нового сервиса сохранить токен отдельного бота из @BotFather как `TELEGRAM_BOT_TOKEN` и свой числовой Telegram ID как `ALLOWED_USER_IDS`. Не использовать токен работающего APICORE.BOT. Несколько ID разделяются запятыми.
4. Blueprint автоматически создаёт `WEBHOOK_SECRET`. При ручном создании сервиса задать случайную строку минимум 32 символа. Python преобразует её в SHA-256 для допустимого Telegram secret header. Это другой секрет, не токен бота.
5. Перенести остальные env vars из Blueprint. `PORT` и `RENDER_EXTERNAL_URL` предоставляет Render; вручную задавать их не нужно. На другом HTTPS-хостинге используется `APP_BASE_URL` без пути.
6. Выполнить Deploy. В журнале успешной регистрации будет `Webhook ready; waiting for video uploads`, `/healthz` вернёт HTTP 200. До регистрации webhook сервер возвращает HTTP 503.
7. В Telegram отправить `/start` и короткий ролик **как файл**, дождаться пяти MP4 и `report.json`. Для видео больше 20 MiB использовать `/upload` и кнопку «Загрузить видео без сжатия». Проверить звук, размеры и длительность. Сервис создан на Free, сборка и подключение Telegram проверены; доставка пяти результатов реального пользовательского видео требует проверки в чате.

## Загрузка через окно Telegram

Публичный `/upload` отдаёт только интерфейс. `/upload/status` и `/upload/video` проверяют HMAC-SHA-256 подпись `Telegram.WebApp.initData`, время выдачи (до одного часа) и разрешённый Telegram ID. Получатель результатов выводится из подписанного ID, а не из параметров браузера. Кнопка работает в личном чате; групповой чат предлагает перейти в личный.

Видеофайл передаётся сырым HTTP body, сохраняется на диск блоками 64 KiB и не загружается целиком в память. До чтения body проверяются подпись, Content-Length и свободный слот. По умолчанию максимум 200 MiB (`MAX_WEB_INPUT_MB`); время загрузки до 10 минут, пауза чтения до 30 секунд. Повторный принятый `X-Upload-ID` не запускает вторую задачу в текущем процессе. Прерванная загрузка освобождает слот и удаляет временный файл. Telegram `getFile` для этой загрузки не вызывается, поэтому его предел 20 MiB не применяется. После приёма запускается обычная обработка пяти версий вне HTTP-запроса.

Предел отправки 50 MiB на результат остаётся: качество для попадания в него автоматически не ухудшается. Для `/lossless` исходник больше этого предела не получится вернуть через облачный Telegram API.

## Как работает webhook

При запуске сервер вызывает `getMe` и `setWebhook` на свой HTTPS URL `/telegram/webhook`, задаёт secret token и принимает только сообщения. Каждый входящий запрос проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`. Отдельный поток разбирает сообщения; обработка FFmpeg проходит вне HTTP-запроса. Результаты отправляются файлами в исходный чат, с ответом на исходное сообщение.

Повторные updates подавляются в памяти текущего процесса. Если внутренняя очередь из 32 updates заполнена или сервер ещё запускается, ответ HTTP 503 позволяет Telegram повторить доставку. Загрузка другого видео во время активной обработки отклоняется сообщением о занятости: очереди видеозадач нет. Нельзя одновременно запускать polling для того же токена; для возврата к локальному режиму сначала отключить webhook через Telegram `deleteWebhook`.

## Пределы бесплатного тарифа

- Render усыпляет сервис после 15 минут без входящих запросов. Новое сообщение Telegram пробуждает его, обычно примерно за минуту; доставка может задержаться до повторного webhook-запроса.
- Исходящие отправки файлов и работа FFmpeg сами по себе не считаются входящим трафиком. Пока есть активная задача, сервис проверяет свой публичный `/healthz` каждые 240 секунд (`ACTIVE_JOB_HEARTBEAT_SECONDS`); в простое запросы не отправляются. Это поддерживает входящий трафик во время обработки, но не предотвращает принудительный перезапуск Render. Значение `0` отключает эти проверки.
- `PROCESS_TIMEOUT_SECONDS=3600` даёт до часа на одну версию вместо прежних 10 минут. На слабом CPU Free обработка пяти версий может занимать часы; CRF 16, veryfast и размеры исходника сохранены. Увеличение таймаута не восстановит исходник, уже удалённый после предыдущей ошибки.
- Каждую минуту журнал показывает сгенерированный ID задачи, этап, версию, число подтверждённых отправок и прошедшее время. `stage=delivered version=5 sent=5/5` подтверждает пять успешных вызовов отправки; `stage=completed` также подтверждает отправку отчёта и финального сообщения. Ошибка `kind=ProcessingTimeout` отдельно отмечает превышение времени. ID чата, токены и имена исходников не логируются. `/status` показывает текущую версию и число отправленных видео.
- Файлы, очередь updates, режим пользователя и активные задачи не сохраняются после перезапуска, деплоя или засыпания. **Прерванный исходник нужно прислать заново**. Строго гарантировать пять доставленных файлов при перезапуске бесплатный вариант не может.
- 750 бесплатных часов в месяц делятся между всеми Free-сервисами workspace, включая существующий Instagram-сервис. После исчерпания Render приостанавливает бесплатные сервисы до следующего месяца.
- Тариф compute Free бесплатный, но исходящий трафик пяти видео и сборки расходуют общие квоты workspace. При наличии способа оплаты Render может начислять превышение квот. Для режима без платежей нужно проверить Billing аккаунта: без способа оплаты превышение приводит к приостановке, а не покупке дополнительных квот. Не изменять оплату существующего Instagram-сервиса без решения владельца.

Для исходников больше 20 MiB используется кнопка загрузки. Для отправки результатов больше 50 MiB предусмотрен локальный Bot API и Windows/Docker-вариант из README; бесплатный Render-шаблон его не запускает.

## Проверки

`python3 -m unittest discover -v` проверяет реальный FFmpeg, пять файлов в исходный чат, секрет webhook, дубликаты, быстрый HTTP-ответ при занятом обработчике, переполнение очереди и регистрацию webhook. Проверки не заменяют пробную доставку через живого Telegram-бота и замеры нагрузки на Render Free.

Официальные источники: https://render.com/docs/free, https://render.com/docs/blueprint-spec, https://render.com/docs/environment-variables, https://core.telegram.org/bots/api#setwebhook.
