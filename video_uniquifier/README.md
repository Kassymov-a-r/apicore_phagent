# Telegram Video Uniquifier

Загружаешь своё видео в Telegram-бот → бот создаёт **5 версий** → возвращает их **в тот же чат файлами**, плюс JSON-отчёт с полными SHA-256. Исходный ролик целиком сохраняется: монтаж, начало и конец не обрезаются по времени.

Код добавлен в существующий репозиторий `Kassymov-a-r/apicore_phagent`, папка `video_uniquifier`, ветка `feature/telegram-video-uniquifier`. Render-сервис Instagram использует `main`; уникализатор подготовлен для отдельного бесплатного Web Service с webhook из этой ветки. Живой Telegram-бот пока не запущен: токен ещё не настроен.

**Для размещения на Render, как прежний Instagram-проект IG Agent Pro, начни с [RENDER_SETUP.md](RENDER_SETUP.md).** Добавлены `render.yaml` и `Dockerfile.render`; фактический деплой не выполнен. В подключённом Render-аккаунте найден Instagram-сервис https://apicore-phagent.onrender.com.

Для запуска на том же Windows-компьютере, где APICORE.BOT, доступны [WINDOWS_SETUP.md](WINDOWS_SETUP.md) и `start_video_bot.bat`. По сохранённым логам APICORE.BOT работал в `C:\Users\ak\OneDrive\Рабочий стол\APICORE.BOT`; актуальные процессы этого ПК отсюда не проверены.

## Быстрый запуск через Docker

1. Создай отдельного бота у [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Узнай свой числовой Telegram ID у [@userinfobot](https://t.me/userinfobot).
3. Скопируй `.env.example` в `.env`, укажи `TELEGRAM_BOT_TOKEN` и `ALLOWED_USER_IDS`. Токен хранится только на твоём сервере, в Git он исключён.
4. Из папки проекта выполни:

```bash
docker compose up -d --build
docker compose logs -f video-bot
```

Открой своего бота, отправь `/start`, затем приложи ролик **как файл / без сжатия**. Если отправить его как обычное видео, Telegram может сжать исходник ещё до получения ботом; восстановить потерянные детали бот не сможет.

Остановка: `docker compose down`. Нужен постоянно работающий компьютер или сервер. Docker Desktop подходит для Windows/macOS; Docker Engine — для Linux.

## Для больших исходников — локальный Bot API

Облачный Telegram Bot API позволяет скачивать до 20 МБ и отправлять новые файлы до 50 МБ. Локальный официальный сервер снимает предел скачивания и позволяет загрузку до 2000 МБ. В проекте используются консервативные лимиты в MiB: 500 MiB на вход и 1900 MiB на выход в локальном режиме. Бот никогда автоматически не ухудшает качество для попадания в лимит.

1. Получи собственные `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org). Это дополнительные ключи Telegram, не токен BotFather.
2. В `.env` замени настройки и добавь ключи:

```dotenv
BOT_API_LOCAL=true
BOT_API_BASE_URL=http://bot-api:8081
BOT_API_FILE_ROOT=/var/lib/telegram-bot-api
MAX_INPUT_MB=500
MAX_OUTPUT_MB=1900
TELEGRAM_API_ID=YOUR_API_ID
TELEGRAM_API_HASH=YOUR_API_HASH
```

3. Останови облачный экземпляр бота. Один раз отключи его от облачного Bot API:

```bash
docker compose down
docker compose build video-bot
docker compose run --rm --no-deps video-bot python -m uniquifier.logout_cloud
```

4. Запусти бота и локальный API:

```bash
docker compose -f compose.yaml -f compose.local.yaml up -d --build
docker compose -f compose.yaml -f compose.local.yaml logs -f
```

Первый запуск собирает официальный сервер из [tdlib/telegram-bot-api](https://github.com/tdlib/telegram-bot-api); сборка может занять заметное время и требует интернета. Обе службы используют один том для исходников, бот читает его без права записи. Порт API не публикуется наружу. При необходимости в `.env` задай `BOT_API_REF` с выбранным тегом официального сервера; по умолчанию сборка использует `master`.

Токен не выводится в журналы. Для переключения обратно на облачный API учитывай ограничения метода `logOut` и предварительно отключи бота от локального API по документации Telegram.

## Режимы и команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Инструкция и текущие пределы размера |
| `/micro` | Пять MP4 с мягкими изменениями; режим по умолчанию |
| `/lossless` | Пять MP4 без перекодирования исходников MP4/MOV |
| `/status` | Есть ли активная обработка в этом чате |
| `/cancel` | Остановить текущую обработку |
| `/id` | Показать свой Telegram ID |

Выбор режима действует для следующих загрузок этого пользователя до перезапуска бота. Текущая задача сохраняет выбранный при загрузке режим.

В `/micro`: H.264, CRF 16, AAC 256 kbit/s; preset slow для локального запуска, veryfast для Render Free. Сохраняются размеры кадра с учётом поворота телефона; изображение немного приближается, без рамок. Частота вывода постоянная, равна средней частоте исходника: у VFR-видео исходные интервалы кадров не сохраняются. Голос меняет скорость вместе с видео без намеренного изменения высоты тона.

| Версия | Скорость | Приближение | Яркость | Контраст | Насыщенность |
| --- | --- | --- | --- | --- | --- |
| 1 | 0,98× | 1,010× | +0,002 | 1,003× | 1,003× |
| 2 | 0,99× | 1,015× | −0,002 | 0,997× | 0,997× |
| 3 | 1,01× | 1,020× | +0,003 | 1,005× | 1,002× |
| 4 | 1,02× | 1,012× | −0,003 | 1,002× | 1,005× |
| 5 | 1,00× | 1,018× | +0,001 | 0,998× | 0,995× |

Яркость — параметр FFmpeg `eq`, не процент. Профили постоянные и сравнимые; каждому файлу добавляется новый случайный идентификатор в метаданные.

`/micro` перекодирует видео и немного кадрирует края; математически он не без потерь. Настройки нацелены на высокое качество, но результат зависит от исходника. `/lossless` копирует сжатые видеоданные и аудиоданные без изменения кадров и звука, меняет метаданные и пересобирает MP4; поддерживает MP4/MOV с совместимыми с MP4 кодеками. Все пять версий в этом режиме выглядят одинаково.

HDR/10/12/16-bit и анаморфные исходники в `/micro` отклоняются: бот предлагает `/lossless`, чтобы не преобразовывать цвет/разрядность или пропорции незаметно для пользователя. В обоих режимах выбираются первая основная видеодорожка и первая аудиодорожка; дополнительные дорожки, главы, вложения и отдельные субтитры не переносятся. Уже вшитые в изображение субтитры сохраняются.

Изменение SHA-256 показывает изменение файла. Оно **не доказывает** изменение воспринимаемого отпечатка ролика и не гарантирует обход распознавания дублей Instagram/TikTok или рост просмотров. Функции замены хука/озвучки/монтажа в этой версии отсутствуют.

## Работа и ограничения

- Для локального запуска одновременно обрабатывается один ролик, максимум 10 минут, до 4K и 120 FPS. В Render Free: до 90 секунд и 1080p, один ролик, без сохранения задач после перезапуска. Лимиты задаются в `.env`; `MAX_JOBS` допускает 1–4 задачи. Если бот занят, он просит прислать файл позже; скрытой очереди нет.
- Только пользователи из `ALLOWED_USER_IDS` могут запускать обработку. Команда `/id` доступна для определения ID.
- Результаты отправляются по одному, сразу после обработки. При сбое бот сообщает, сколько из пяти уже отправлено. Завершившиеся файлы удаляются с сервера; исходник и временные файлы удаляются по завершении или отмене. После аварийного перезапуска остатки задач очищаются.
- Сетевая отмена может ждать завершения текущего HTTP-запроса, максимум до 300 секунд. FFmpeg проверяет отмену каждые 250 мс.
- Активные задачи не возобновляются после перезапуска; такой исходник следует прислать снова. Смещение Telegram updates сохраняется, чтобы не обрабатывать уже принятые сообщения повторно после штатного перезапуска.
- Повтор отправки происходит только после явного Telegram ответа 429. После неопределённого сетевого сбоя повтор автоматически не выполняется, чтобы не продублировать доставленный файл.
- При нехватке места, превышении времени/размера или повреждённом файле бот возвращает ошибку вместо молчаливого ухудшения качества.
- На одном токене должен работать один polling-бот, без активного webhook. Исходники с сетевыми ссылками не загружаются через FFmpeg.

## Запуск без Docker

Windows/Linux/macOS, Python 3.10+, FFmpeg/ffprobe 6.1+ в `PATH`. Python-пакеты устанавливать не нужно: используется стандартная библиотека.

```bash
cp .env.example .env
# Заполни .env в редакторе
python3 -m uniquifier.bot
```

На Windows используй `start_video_bot.bat` и [WINDOWS_SETUP.md](WINDOWS_SETUP.md). Для локального Bot API доступен вариант Docker Desktop из раздела выше.

## Проверки

```bash
python3 -m unittest discover -v
```

Тесты создают настоящие короткие видео и проверяют пять разных файлов, полное декодирование, размеры/FPS, синхронизацию звука, видео без аудио, поворот телефона, HDR-защиту, отмену/таймаут, повреждённые файлы, лимиты, права доступа и защищённый webhook (дубликаты, переполнение, быстрый ответ). Для `/lossless` сравниваются декодированные кадры и PCM-звук с исходником. Bot API проверяется HTTP-сервером и подменой доставки: пять файлов и отчёт уходят в исходный чат, ошибки сообщают частичный результат, временные файлы удаляются.

Живая отправка через Telegram не проверена: для неё нужен твой токен. Docker-сборка и сборка локального Bot API в текущем окружении не запускались; здесь нет Docker. Рецепты запуска включены для сервера.
